模块由两个相互协作的子目录组成：
- `docker/`：以多阶段 Dockerfile 为核心，定义 `base` → `rust-build` / `csrc-build` / `extensions-build` → `build` → `vllm-base` → `test` / `vllm-openai-base` 等阶段，通过 `ARG` 参数化 CUDA/Python/Ubuntu 版本，并由 `versions.json`（由 `tools/generate_versions_json.py` 自动生成）集中管理所有 ARG 默认值；`docker-bake.hcl` 通过 `target` + `inherits` 组合出 `openai`、`test`、`ubuntu2404` 等构建目标，支持 `docker buildx bake` 并行构建。各平台变体（`Dockerfile.rocm`、`Dockerfile.tpu`、`Dockerfile.xpu`、`Dockerfile.s390x`、`Dockerfile.ppc64le`、`Dockerfile.cpu`）复用相同阶段模型。
- `cmake/`：`utils.cmake` 提供核心宏（`define_extension_target`、`hipify_sources_target`、`get_torch_gpu_compiler_flags`、`cuda_archs_loose_intersection` 等），统一处理 Python 解释器发现、CUDA/HIP gencode 标志、架构交集计算与 libgomp shim；`hipify.py` 调用 PyTorch 的 hipify 工具将 `.cu` 转为 `.hip` 并保证输出路径一致；`cpu_extension.cmake` 负责 CPU 后端（x86/ARM/PowerPC/S390/RISC-V）的 ISA 探测与 OpenMP 链接；`external_projects/*.cmake` 通过 `FetchContent` 拉取 DeepGEMM、triton_kernels、flash-attn、fmha_sm100、qutlass、tml_fa4 等第三方内核，并按每个 `requires-python` 解释器分别构建 `_C` 二进制。
依赖方向：Dockerfile 在 `csrc-build` 阶段调用 `setup.py bdist_wheel`，后者触发 CMake 构建；HIP 构建先经 `hipify.py` 预处理再进入 CMake；外部项目通过 `install(DIRECTORY ...)` 打包进 `vllm/third_party/`。
