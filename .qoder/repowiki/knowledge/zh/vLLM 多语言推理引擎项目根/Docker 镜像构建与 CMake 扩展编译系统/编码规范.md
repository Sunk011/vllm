- Dockerfile 中所有可配置版本均通过 `ARG` 声明并在文件顶部集中注释说明，再由 `versions.json` 自动同步默认值，禁止直接硬编码版本号。
- 多阶段 Dockerfile 使用 `FROM base AS <stage>` 命名阶段，并通过 `--mount=type=cache,target=...` 挂载 uv/cargo/ccache 缓存目录，避免重复下载与编译。
- CMake 脚本通过 `run_python` 宏执行 Python 表达式获取运行时信息（如 torch NVCC/HIP 标志、SOABI、libgomp 路径），而非在 configure 时硬编码。
- 外部依赖统一通过 `cmake/external_projects/<name>.cmake` 封装，使用 `FetchContent_Declare` + `GIT_TAG` 固定上游版本，并支持通过 `<NAME>_SRC_DIR` 环境变量切换到本地源码目录。
- HIP 构建流程强制先调用 `hipify_sources_target` 将 `.cu` 转换为 `.hip` 到 `CMAKE_CURRENT_BINARY_DIR/csrc`，再通过 `vllm_finalize_hipify_target` 串联为单一 `hipify_all` 目标，避免并行写入冲突。
- CUDA 架构列表通过 `clear_cuda_arches` + `set_gencode_flags_for_srcs` + `cuda_archs_loose_intersection` 三件套统一提取、过滤与匹配，支持 `+PTX` 后缀与 `a/f` 家族后缀。
