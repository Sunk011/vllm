- 每个后端专用 requirements 文件均以 `-r common.txt` 开头继承公共依赖，再通过平台标记（`platform_machine` / `platform_system`）条件安装特定包。
- 对需要严格对齐的版本（如 torch/torchaudio/torchvision、grpcio/grpcio-reflection、numba）使用完全相同的版本号进行 pin。
- 测试依赖采用 `.in` 声明式源文件 + `uv pip compile` 生成锁定 `.txt` 文件的分离模式，`.txt` 文件头部保留生成命令注释以便复现。
- 从非 PyPI 索引安装的包通过 `--extra-index-url` 指定额外索引源，并在同一文件中紧跟包名。
- 对存在安全漏洞或兼容性风险的依赖使用 `!=` 排除特定版本或 `<` 上限约束（如 protobuf 排除多个 CVE 版本、fastapi 限制 < 0.137.0）。
