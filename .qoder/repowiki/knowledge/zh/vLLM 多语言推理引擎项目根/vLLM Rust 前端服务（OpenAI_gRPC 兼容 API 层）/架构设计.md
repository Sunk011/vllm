模块采用分层 Cargo workspace 架构（`rust/Cargo.toml` 定义 12 个子 crate），自底向上依赖方向严格单向：
- `engine-core-client`：ZMQ 传输 + MessagePack 协议封装，暴露 `EngineCoreClient` 与 `coordinator`（inproc/external/bootstrap/handle），是跨进程边界的核心。
- `llm` / `text` / `chat`：逐层抽象，`llm` 为 thin token-in/token-out facade，`text` 负责 tokenizer 与增量 detokenizer，`chat` 负责模板渲染、结构化输出解析（reasoning/tool/unified）与多模态处理。
- `server`：基于 axum 的 OpenAI 兼容 HTTP 服务器，同时通过 tonic 暴露 gRPC `Generate` 服务（由 `proto/vllm_grpc.proto` 生成），路由按功能拆分为 `routes/inference`、`routes/openai`、`routes/tokenize` 等子模块，中间件统一放在 `middleware/`（auth/cors/load/metrics/offload/request_id）。
- `cmd`：二进制入口 `vllm-rs`，提供 `Frontend`（纯 HTTP/gRPC 服务）与 `Serve`（管理 Python headless 引擎生命周期）两种模式，通过 `managed-engine` crate 启动/监控 Python 子进程。
- 辅助 crate：`parser`（多模型 reasoning/tool/json 解析器）、`metrics`（Prometheus 指标采集）、`mock-engine`（测试用模拟引擎）、`bench`（基准测试套件）。
- gRPC 接口由 `tonic-prost-build` 在 `server/build.rs` 中从 `proto/vllm_grpc.proto` 编译生成，HTTP 与 gRPC 共享同一 `AppState` 并通过 `CancellationToken` 协调优雅关闭。
