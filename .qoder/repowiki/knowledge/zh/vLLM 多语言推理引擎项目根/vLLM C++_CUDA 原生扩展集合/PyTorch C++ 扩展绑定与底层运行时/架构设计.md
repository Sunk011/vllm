本模块由多个独立的 PyTorch 原生扩展组成，按职责划分为：
- `torch_bindings.cpp`：主扩展入口，使用 `TORCH_LIBRARY_FRAGMENT` 注册 custom_ar 操作（ROCm Quick Reduce），并通过 `REGISTER_EXTENSION(TORCH_EXTENSION_NAME)` 完成整体初始化。
- `qutlass_registration.cpp`：为 `_qutlass_C` 扩展提供最小 stub，仅用于触发 Python 导入时执行 `TORCH_LIBRARY` 中的 op 注册。
- `cumem_allocator.cpp`：基于 cuMem 通用分配 API 实现 CUDAPluggableAllocator，通过 `init_module` 接收 Python 回调（malloc/free），在 `my_malloc`/`my_free` 中调用 Python 并管理 CUmemGenericAllocationHandle；通过 `#ifndef USE_ROCM`/`#ifdef USE_ROCM` 分支分别处理 CUDA 单句柄与 ROCm 分块多句柄路径。
- `custom_quickreduce.cu`：ROCm-only 的 QuickReduce all-reduce 封装，导出 `init_custom_qr`、`qr_all_reduce`、`qr_destroy`、`qr_get_handle`、`qr_open_handles`、`qr_max_size` 等函数，并按 world_size 和量化编解码器模板实例化。
- `fs_io.cpp`：纯 C Python 扩展 `fs_io_C`，提供 `batch_lookup` 批量检查文件存在性，使用 `Py_BEGIN_ALLOW_THREADS` 释放 GIL 以并行调用 `access(2)`。
- `spinloop.cpp`：纯 C Python 扩展 `spinloop`，实现基于 monitorx/mwaitx 或 busy-poll 的硬件优化自旋等待循环，支持超时回调。
依赖方向：所有子模块均向下依赖 CUDA/ROCm 驱动 API 和 Python C API，向上通过 `REGISTER_EXTENSION` 或 `PyMODINIT_FUNC` 暴露给 Python，彼此之间无直接耦合。
