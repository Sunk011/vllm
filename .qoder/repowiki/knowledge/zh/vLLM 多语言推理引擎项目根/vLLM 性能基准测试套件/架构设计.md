本模块按测试维度划分为多个独立子目录：
- 顶层 `benchmark_*.py` 脚本为 vLLM CLI (`vllm bench`) 的前身，现已标记为 DEPRECATED，仅输出迁移提示并退出。
- `attention_benchmarks/` 是独立的注意力基准套件，以 `benchmark.py` 为统一入口，通过 YAML 配置（`configs/*.yaml`）驱动标准注意力（Flash/Triton/FlashInfer）与 MLA 后端（cutlass_mla、flashinfer_mla、flashattn_mla、flashmla），由 `batch_spec.py` 解析扩展语法（如 `q2k`、`8q1s1k`、`2q2k_32q1s1k`），`common.py` 定义 `BenchmarkConfig`/`BenchmarkResult`/`ResultsFormatter` 等核心数据结构，`runner.py` 与 `mla_runner.py` 分别调度两类后端。
- `kernels/` 存放各底层算子的独立 benchmark 脚本（GEMM、MoE、量化、RoPE、Layernorm 等），每个文件通常以 `argparse` 解析参数并通过 Triton `@triton.testing.perf_report` 或 `do_bench_cudagraph` 进行计时，依赖 `weight_shapes.py` 提供模型形状枚举。
- `multi_turn/` 实现多轮对话服务基准，基于 `aiohttp` 异步客户端并发压测，配合 `bench_dataset.py` 生成/加载 ShareGPT 风格对话。
- `auto_tune/` 提供 Shell 脚本 `auto_tune.sh`，通过遍历 `max_num_seqs`、`max_num_batched_tokens`、`gpu_memory_utilization` 等参数组合，调用 `vllm serve` + `vllm bench serve` 自动寻找满足延迟约束的最优配置。
- `overheads/`、`structured_schemas/` 等为专项开销与结构化输出基准。
- 依赖方向：所有 benchmark 脚本均通过 `sys.path.insert(0, ...)` 或直接 import `vllm.*` 访问被测代码，不反向依赖 vLLM 的入口层，保持单向评测关系。
