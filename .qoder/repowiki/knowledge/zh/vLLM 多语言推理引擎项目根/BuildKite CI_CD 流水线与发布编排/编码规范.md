- 每个 CI 变体（主 CI、Intel、ROCm）均提供独立的 ci_config_*.yaml，统一使用 name/job_dirs/run_all_patterns/run_all_exclude_patterns/registries/repositories 字段描述触发规则与制品仓库。
- Pipeline step 通过 agents.queue 指定执行队列（如 cpu_queue_release、arm64_cpu_queue_release、mi250_1、mi300_2 等），并按硬件能力分配 num_gpus 与 agent_pool。
- 长耗时或易失败步骤使用 allow_dependency_failure: true 与 soft_fail: true 隔离风险，block 步骤配合 if: build.env("NIGHTLY") != "1" 实现人工放行与条件分支。
- 所有外部命令封装在 .buildkite/scripts/*.sh 中，pipeline step 仅通过 bash 调用脚本路径，避免在 YAML 中嵌入复杂逻辑。
- 制品上传统一通过 .buildkite/scripts/upload-nightly-wheels.sh 与 annotate-build-artifact.sh 完成，S3 路径遵循 s3://vllm-wheels/$BUILDKITE_COMMIT/ 命名约定。
- AMD ROCm 测试通过 test-amd.yaml 声明 steps，再由外部 Jinja 模板渲染，新增测试时需在 source_file_dependencies 中列出受影响的源码前缀以启用变更检测。
