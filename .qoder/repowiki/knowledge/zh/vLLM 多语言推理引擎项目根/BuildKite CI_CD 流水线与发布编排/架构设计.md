本模块以 BuildKite YAML Pipeline 为核心编排文件，采用「配置驱动 + 模板生成」的分层结构：
- 顶层配置文件 `ci_config.yaml`、`ci_config_intel.yaml`、`ci_config_rocm.yaml` 分别定义主 CI、Intel XPU CI 和 ROCm CI 的 job_dirs、run_all_patterns/run_all_exclude_patterns、registries 及 repositories，用于控制变更触发范围。
- `release-pipeline.yaml` 是完整的发布流水线，按阶段组织为多个 group（build-wheels、build-release-images、publish-release-images、ROCm Release Pipeline 等），通过 block 步骤实现人工放行与条件分支（NIGHTLY 变量控制 nightly 行为）。
- `test-amd.yaml` 是 AMD ROCm 测试集，通过 Jinja 模板 `test-template-amd.j2`（位于外部 buildkite-ci 仓库）渲染为最终 pipeline，支持 MI250/MI300/MI325/MI355 等多代 GPU 池。
- `test-pipeline.yaml` 已废弃，迁移到 `.buildkite/image_build`、`.buildkite/test_areas`、`.buildkite/hardware_tests`、`.buildkite/intel_jobs`、`.buildkite/lm-eval-harness`、`.buildkite/performance-benchmarks` 六个子目录，每个目录对应一类 Job。
- `scripts/` 存放所有可复用 shell/Python 脚本（上传 wheel、生成索引、Docker 元数据、缓存、ECR/DockerHub 推送等），被各 step 通过 `bash .buildkite/scripts/...` 调用。
- 依赖方向单向：pipeline YAML → scripts → docker/Dockerfile*；CI 配置不反向依赖具体脚本实现。
- ECR 作为镜像与 wheel 缓存后端（`public.ecr.aws/q9t5s3a7`），S3 (`vllm-wheels`) 作为 wheel 制品存储，DockerHub (`vllmbot`) 用于 nightly 发布。
